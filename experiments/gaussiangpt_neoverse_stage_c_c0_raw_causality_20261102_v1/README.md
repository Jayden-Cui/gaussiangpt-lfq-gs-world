# 阶段 C0 的原始状态因果验收

**V1 未通过真实缓存预检，不可用于正式评估。** CPU 重算与 GPU 缓存的差异及后续 GPU 对照见 [FAILURE.md](FAILURE.md)；可用入口以 [V2 结果](../gaussiangpt_neoverse_stage_c_c0_raw_causality_20261102_v2/RESULTS.md)为准。

原阶段 C V4 评估会对 C0 的后缀**缓存 memory** 做扰动；它无法单独证明每个缓存本身只来自对应原始状态前缀。此前两窗口 Q 小试做过原始状态扰动，但不能代替正式阶段 C 的模型验收。

`driver_v5.py` 调用不修改的 V4 评估和重放，并在 V4 的原检查之外，为 C0 追加：

1. 在两个固定窗口用实际冻结 decoder 的初态时空编码器，从原始状态重建运动和重复初态的九个 memory，与缓存坐标、特征和输出码比较；
2. 分别改变 h1、h3、h7 之后的原始状态特征和世界格点，重新计算九个 memory，检查前缀内的码是否保持不变，并确认扰动确实改变了后续 memory；
3. 保证检查前后冻结 decoder 与后验参数摘要不变。C1、C2 维持 V4 的原始状态扰动检查。

每次正式 C0 评估都会对**对应已训练的 Q**重新执行上述检查；结果附在 `CAUSALITY.json`。两个训练窗口和三个跨度不能证明跨视频泛化。真实缓存的 CPU 工程检查也不代表教师已经通过或正式阶段 C 已训练。

调用方式与 V4 相同：`python -B driver_v5.py evaluate --run-root ... --step ... --receipt ...`；独立重放使用 `replay --run-root ... --step ... --mode C0`。正式运行仍须通过原有教师收据和资源检查。
