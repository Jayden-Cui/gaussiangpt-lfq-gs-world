# 阶段 C 的时间／变化对照初始化

原计划要求先检查显式时间信息，再检查占据／特征变化。使用真实的旧 Q-Former 和编码器在 CPU 上构造两种 C2 设置后发现：即使随机种子相同，旧实现的“只加时间”和“时间＋变化”模型的时间投影初值也不同，最大绝对差为 **0.043537**、均方根差为 **0.014030**。原因是后者先初始化变化投影，消耗了随机数；两版的共享 Q-Former 和时空编码器初值相同。这个发现只涉及初始化可比性，不证明它造成了此前的运动重建问题。

新增入口 `driver_v3.py` 继续调用既有阶段 C 训练、教师收据和 GPU 预检流程，仅在 C2 同时启用时间和变化时，把共享时间投影初始化为对应“只加时间”版本的初值。新增变化投影继续使用原有初始化；不改变模型维度、教师 decoder 或数据。C0、C1 和只加时间的 C2 保持原样。是否需要额外训练只加时间的对照，仍由阶段 C 的实验分支决定。

真实旧模型的 CPU 检查确认：

- 两种 C2 的共享时间投影逐元素完全一致；Q-Former 和编码器也一致。
- 完整 C2 中，除时间投影外的原参数与旧初始化逐元素一致，包括变化投影；调用后的 CPU 随机数状态与旧入口一致。
- C0、C1 和只加时间版本的整个初始模型保持不变。
- 模拟调用验证了新入口会把策略、源码哈希和初始模型摘要写入训练绑定记录，并在退出时恢复旧入口函数。[CPU 检查](CPU_TESTS.json)

正式使用新入口时，训练配置需显式包含 `"initializer_policy": "match_time_only_shared_projection_v1"`，并继续满足旧入口对同一可靠教师、数据缓存和完整预检的要求。当前没有选定全片段教师，没有启动此入口的训练；真实教师上的 GPU 预检与 C0／C1／C2 动态评估仍待完成。
