# 历史 Q-Former 的同相机静止控制：排队记录

## 为什么做这个检查

原两窗口 Q-Former 评估已经保存了两种码：读取真实未来前缀的码，以及将初态 S0 重复作为后验输入得到的码。对同一真实运动目标，18 个未来帧的运动加权 MAE 分别为 0.029765 和 0.032537。末帧旧图中，重复初态码的输出仍与运动末态相似；但旧评估没有用同一未来帧相机渲染 S0 作为静止目标，因此不能只凭这些指标宣布静止控制通过或失败。

两个窗口的 h0 与 h9 相机、内参并非逐位相同；对两个视角的相机矩阵，最大绝对差分别约 0.001588、0.001345；内参最大绝对差均约 0.007937。这些是记录值的差，不直接等同于物理位移。新检查将 S0 和真实未来状态都放在每个未来帧相机下，经相同冻结 codec 生成两个参考，再分别评估两种已保存 Q 码。

## 排队和核验

服务器 134 的 `gg_qformer_static_control_20261102` 已启动，启动验收时等待进程为 `764915`。它通过 pidfd 等待 GPU 1 上关键窗口重放小试的进程 `764436` 退出，之后在 GPU 1 运行本检查；等待过程不轮询，也不向小试或原阶段 B 发送信号。最长等待 2100 秒、GPU 检查上限 300 秒，PyTorch 分配器上限 12 GiB。

历史 Q 码、原评估、两窗口原始 GS 状态和当前帧缓存的哈希已核对；本地与服务器 CPU 解析测试、服务器真实 pidfd 退出事件测试均通过。两种 Q 预测还必须逐帧复现旧评估的图像误差，才写出结果。启动时检查仍在等待，尚无同相机静止控制结论。

正式输出为服务器本目录 `result/STATIC_CONTROL.json` 和两段视频。五栏依次为源画面、真实未来 GS 的 codec 参考、真实未来前缀 Q 码输出、S0 的静止 codec 参考、重复 S0 的 Q 码输出；不含顶部标记。此为历史 Q 模型在两个训练窗口上的先行诊断，不替代阶段 C 后验训练、完整 D 验收、独立原生重放或跨源验证。
