# 两窗口固定 decoder 的静止连续码诊断

该诊断回答：固定先前两窗口成功的运动 decoder、GaussianGPT 状态 codec 和初始条件后，仅优化 `[2,9,16]` 的连续码，能否让两个场景保持初始状态？起点是旧 Q-Former 对重复初态的码。此实验不训练 Q-Former，不修改正在运行的阶段 B，也不使用量化或 AR。

两个窗口、九个 horizon 各访问 30 次，总共 540 次单样本更新；仅静态 S0 的状态与同相机渲染作为训练目标，动态未来仅用于检查点离线对照。每个检查点对 18 帧分别计算运动区域加权误差并保存四栏视频，后续必须检查物体是否真实保持静止，不能仅用平均误差下结论。固定 decoder 的一次有限预算优化失败，也不能证明静止输出在数学上不可达。

结果不是全片段教师、正式阶段 C 或跨视频泛化。训练和评估设置、来源哈希、资源上限见 `protocol.json`；GPU 作业在已排队的第 10 轮预览进程结束后运行，避免争用 GPU 1。

首次 v1 排队时 CPU 检验证据文件末尾错误写入了转义文本，导致 JSON 解析失败，程序在 GPU 申请前退出。v2 在独立目录重新生成合法 JSON，保留 v1 日志；同时将自检异常纳入队列失败记录。

v2 的 GPU 预检已验证渲染损失能传回静止码且 decoder、codec 冻结；但第 0 步评估错误地从实验协议读取模型的节点上限，报 `KeyError` 并在正式更新前退出。v3 从绑定的模型配置读取该上限，新增对应回归检查；v2 的失败记录完整保留。
