# C0 原始状态因果检查补强结果

## 发现与修改

阶段 C 原 V4 评估对 C0 只改变**缓存后的后续 memory**；即使该检查通过，也不能单凭它确认缓存构造时没有读到未来状态。新增 V5 包装入口，保留 V4 的已有检查，并对 C0 的实际冻结 decoder 和已训练后验增加原始状态检查；C1、C2 和 GS 独立重放沿用 V4。旧代码和历史结果没有被修改。

## 实际数据预检

使用原始 codec、绑定缓存和已有 Q 初始化，在 134 的 GPU 1 上只做推理：

- 窗口 35 和 123，分别重算 9 个运动前缀及 9 个重复初态前缀；总共 36 组 memory 的坐标和特征与缓存逐元素一致，对应连续码最大差异为 0。
- 分别扰动 h1、h3、h7 **之后**的原始状态特征与世界格点；6 组实验中，先前码的最大变化均为 0，且扰动确实改变了后续 memory。
- 固定 decoder 与 Q 的摘要未变，优化器更新次数为 0，GPU 峰值分配约 0.175 GiB。[完整记录](REAL_SOURCE_CHECK.json)

这些结果只覆盖两个已训练窗口和已有 Q 初始化；正式 C0 模型训练后，V5 会在其评估时重新做检查。它们不说明全片段动作已恢复或跨视频泛化。

V1 的 CPU 重算因设备数值差异未满足严格特征容差。对照显示 GPU 重算与缓存一致；详细差异和 V1 失败见[记录](../gaussiangpt_neoverse_stage_c_c0_raw_causality_20261102_v1/FAILURE.md)。V2 沿用原容差，在与正式评估相同的 GPU 设备类型上检查。

本地和服务器合成测试还验证了缓存被篡改、直接读取未来状态时会被拒绝，以及包装器异常退出时会恢复原评估器函数。这些测试不替代训练、运动审查或原生 GS 重放。
